# Проверка NORTHIA

Проверки выполнены 26–27 октября 2026 (Europe/Moscow). Среда: Windows, Node 24.21.0, Chromium через Playwright CLI.

## Сборка и API

- Этапы 1–4: lint, TypeScript, production build прошли; этапы зафиксированы отдельными коммитами.
- Этап 5: финальные lint/typecheck/build и unit/API-тесты повторно прошли 27 октября после форматирования. git diff --check — без ошибок.
- Unit: 2 теста — экранирование =/+/-/@ с ведущими пробелами и московская дата на границе UTC-суток.
- API: 7 тестовых групп в dev и те же 7 в production без Google-ключей.
- Проверены неизвестный slug, недоступный размер, дробное/нулевое количество, пустая корзина, дубли позиций, пробельные/длинные поля, неверный телефон, malformed JSON, тело >32 KiB и неверный content type.
- Honeypot возвращает успех без валидных полей; dev без ключей принимает валидную заявку; production без ключей возвращает 500.
- Одиннадцатый запрос одного IP/формы возвращает 429 и Retry-After.
- Реальная Google-таблица не подключалась; запись append, доступ сервисного аккаунта и названия реальных вкладок требуют отдельного интеграционного теста после настройки владельцем.

## Браузер

- Полный сценарий главная → товар → размер → корзина → форма → Спасибо выполнен в 390×844 и 360×740.
- Лист ожидания → Спасибо выполнен в обоих размерах.
- Пустая отправка предзаказа показывает пять ошибок; кнопка без выбранного размера подсвечивает блок и переводит фокус.
- Повторное добавление увеличивает qty; корзина сохраняется после перезагрузки.
- Удаление синхронизируется между двумя вкладками; повреждённый JSON, неизвестные товары, неверные размеры и отрицательное количество не ломают страницу.
- Пустая корзина перенаправляет /preorder на /cart; неизвестный товар возвращает HTTP 404.
- Модалка сетки: блокировка фона, Tab внутри, Esc и возврат фокуса.
- Меню: полноэкранная колонка, Tab внутри, Esc и возврат фокуса.
- Слайдер: стрелки, клавиатура и scroll-snap; реальный touch-жест на физическом телефоне не проверялся.
- Аккордеоны меняют aria-expanded и открывают содержимое.
- Серверные ответы 400 с ошибкой поля, 429 и 500 проверены в UI через сетевые подстановки: сообщение показано, данные сохранены.
- Два синхронных requestSubmit отправляют один запрос; кнопка «Отправка…» заблокирована.
- Один h1 на проверяемых экранах; горизонтального переполнения нет на 360/390/430 px.
- На desktop 1440 px колонка имеет ширину 430 px и центрирована.
- prefers-reduced-motion отключает плавную прокрутку.
- Все семь страниц товаров открыты; при чистом последнем просмотре главной — 0 ошибок/предупреждений консоли. В ожидаемых отрицательных проверках 400/429/500/404 сообщения HTTP в консоли допустимы; необработанных JS-ошибок в полных сценариях нет.
